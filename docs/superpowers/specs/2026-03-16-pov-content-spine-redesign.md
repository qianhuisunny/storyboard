# POV-Driven Content Spine Redesign

## Summary

Replace the broken AI-generated "Choose Your Angle" step with a user-authored Point of View input. The POV is the **central claim the video will build and defend** — not a slogan or opinion. It becomes the foundation of Round 3 (Content Spine): user writes their POV, then AI generates the argument structure (talking points, misconceptions, must_avoid) to support it. The separate Angle step is eliminated, progress bar shrinks from 5 to 4 steps, step navigation becomes clickable, and `source_assets` is removed.

## Current State

- **Round 3** has 4 fields: `source_assets`, `must_avoid`, `core_talking_points`, `misconceptions` — all AI-generated by BriefBuilder, user edits
- **Step 4 (Angle)**: Shows 3 AI-generated perspective cards. Perspective generation is disabled in the pipeline, so this step shows empty/stale data. Broken.
- **Progress bar**: 5 steps, steps are not clickable (have `cursor-pointer` but no `onClick`)
- **`source_assets`**: Field exists in Round 3 form and BriefReview — to be removed
- **`selected_angle`**: Stored in brief, consumed by Director and Writer code
- **Round 2 confirm** currently pre-generates Round 3 fields via `BriefBuilder.run(round=3)` — this must be removed since Round 3 now depends on POV first
- **`_handle_round3_confirm`** currently calls `generate_perspectives()` (live LLM call, not dead code) — must be removed
- **`StoryboardState`** has dead fields: `pending_perspectives`, `selected_perspective`, `pending_talking_points`

## New Flow

### Progress Bar: 4 Steps
`Core Intent → Delivery → Content Spine → Review`

Steps are clickable — clicking a completed step navigates back to view/edit it. Clicking the current or future step does nothing.

### Round 3: Two-Phase Content Spine

**Phase 1 — POV Input:**

- Section header: "Section 3: Content Spine"
- Subheader: "Start with your point of view — the one claim this video will build and defend."
- Context reminder (read-only, compact, visually lightweight — not editable):
  - **For:** [target_audience from Round 1]
  - **Topic:** [viewer_outcome from Round 1]
  - **Goal:** [viewer_next_action or viewer_outcome from Round 1]
- Single required textarea for `point_of_view`
- Info tooltip (see Tooltip Content below)
- Button: "Generate Content Spine →"
- Clicking sends `generate_content_spine` event to backend → AI returns fields

**Phase 2 — Review AI-Generated Fields:**
- POV shown as a confirmed/collapsed card at top (editable if user clicks back)
- Below: editable FieldCards for `core_talking_points`, `misconceptions`, `must_avoid`
  - These are AI-generated using POV as source of truth + Rounds 1-2 context
  - User can edit any field before confirming
- Button: "Confirm Section 3 →" → transitions to Review

## Tooltip Content

The tooltip appears on hover/click next to the POV textarea. It teaches what makes a POV usable for downstream generation without being formula-dominant.

### What this is

> A point of view is the core claim your video is trying to make convincing. It gives the video direction and makes it feel different from generic content on the same topic.

### A useful way to frame it

> One useful way to frame it:
> "For [audience], [topic] isn't about [common assumption]; it's about [your insight]."
>
> You don't need to follow this exactly.

### Weak vs. stronger examples

**Example 1:**
- Weak: "AI can help marketers work faster."
- Stronger: "For product marketers, AI is not most valuable for writing copy faster; it is most valuable for turning scattered inputs into sharper strategic angles."

**Example 2:**
- Weak: "Startup exits are hard."
- Stronger: "For first-time founders, startup exits are not mainly about finding a buyer; they are about surviving the 18-month dead zone when neither growth nor M&A interest is strong enough."

The weak versions are topic statements or slogans — too broad to build a video around. The stronger versions are claims with tension — specific enough to support an argument.

## Generation Logic: POV-Centered Argument Construction

The POV is the source of truth. The three generated fields are downstream derivations that refine, support, or protect the claim. They are NOT parallel siblings — they are generated in a chained dependency order.

### Generation Order

```
1. core_talking_points  ← POV + audience + prior brief context
2. misconceptions       ← POV + core_talking_points + audience + prior brief context
3. must_avoid           ← POV + core_talking_points + misconceptions + audience + prior brief context
```

This is a single LLM call with a structured prompt that enforces the dependency chain (instruct the LLM to derive each field from the previous ones in sequence).

### Field Roles (Functionally Distinct)

**`core_talking_points`** — The argument beats required to make the POV convincing.
- NOT subtopics or generic bullet points
- Each point is a reasoning step that builds the case for the claim
- Should create progression: point N builds on point N-1
- Prompt internally as "argument beats" or "reasoning steps," not "things to mention"

**`misconceptions`** — The assumptions or default framings this POV is pushing against.
- NOT generic myths unless the POV genuinely requires myth-busting
- Capture what audiences typically get wrong, oversimplify, or take for granted about this topic
- Create tension against the POV — these are what make the claim non-obvious
- Must NOT be talking points restated in negative form

**`must_avoid`** — What would make this specific POV weaker, blurrier, or less credible.
- NOT generic writing advice ("don't be vague")
- Identify traps specific to this argument that would dilute the thesis
- Protect the integrity of the claim
- Examples: "Don't retreat to 'AI is a tool' framing — this POV claims AI changes the strategy itself" or "Don't list exit types — the claim is about the dead zone, not the mechanics"

### Consistency Check

The generation prompt must include a self-check instruction to ensure:
- `core_talking_points` directly support the POV (each point advances the claim)
- `misconceptions` identify genuine tension, not mirror-phrased talking points
- `must_avoid` is specific to this POV, not generic content hygiene
- The three fields are functionally distinct — no paraphrases of one another

Prompt instruction (appended after the generation request):
> Before returning, verify: (1) each talking point builds the case for the POV, (2) each misconception identifies a real counter-assumption rather than restating a talking point negatively, (3) each must_avoid is specific to this POV rather than generic advice. If any field overlaps substantially with another, revise it.

### BriefBuilder (`brief_builder.py`)

- Primary input: `point_of_view` from confirmed_fields
